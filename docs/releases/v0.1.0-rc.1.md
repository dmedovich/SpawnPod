# SpawnPod v0.1.0-rc.1

First release candidate for the Kubernetes execution backend and the official
Forgejo Runner v13.1.0 plugin protocol. Linux/amd64 is the tested platform.
Security issues found in this version are fixed in rc.2. See the
[rc.2 release notes](v0.1.0-rc.2.md) before using rc.1 artifacts.

## Included

- Reusable, bounded job workspaces; streamed commands, cancellation and file
  transfer; UID-scoped cleanup with durable Kubernetes ConfigMap records.
- Strict administrator profiles, digest-pinned images, non-root job Pods,
  generated admission/RBAC/resource quotas, default-deny networking, and
  optional approved services and source HTTPS egress.
- Real official-Runner workflows for sequential commands, services, error
  exits, cancellation, CopyIn/CopyOut and private HTTPS `actions/checkout@v4`.
- Readiness/liveness, bounded-cardinality Prometheus metrics, a bounded RPC
  shutdown drain, and a generator for the single-replica Kubernetes install.
- Versioned static binaries, runtime Dockerfile, checksums, dependency
  inventory and installation/upgrade documentation.

## Compatibility and limits

- Official Runner v13.1.0, `plugin.v1alpha`; tested with Forgejo v15.0.9 and
  K3s v1.34.12+k3s1. No compatibility claim for later Runner protocols.
- Linux/amd64. ARM64 cross-build evidence is not live platform support.
- Single controller. Job Pods share the host kernel; this is not hard
  isolation for mutually hostile tenants.
- Approved service Pods/ClusterIP endpoints only. No privileged DinD, arbitrary
  mounts, user switching, SSH source checkout or unrestricted internet profile.
- Source egress requires a separately operated proxy and maintained IP routes.
- No Helm chart, built-in registry publisher, destructive cleanup CLI or
  production hardware capacity/SLO claim in this candidate.
- Drain protects active RPCs, not an entire multi-step workflow. Quiesce Runner
  and wait for jobs before planned upgrades. Forced drain cancels active RPCs;
  reconciliation cleans interrupted records after restart.
- Kubernetes objects alone do not prove isolation. Run the documented live
  admission, networking and recovery checks on each target installation.
