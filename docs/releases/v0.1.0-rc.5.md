# SpawnPod v0.1.0-rc.5

Operations and recovery improvements for Forgejo Runner v13.1.0.

- Support namespace-wide default-deny NetworkPolicy at controller startup.
  Generated policies now select every Pod in the workload namespace; the
  original managed-Pod selector remains supported. Both traffic directions
  must be denied, without additional selector requirements or allow rules.
- Make cleaned ConfigMap retention configurable with
  `controller.tombstoneRetention` (`1m`–`24h`, default `24h`). These records are
  retry tombstones; they expire on a successful reconciliation sweep after
  the retention period. For small ConfigMap quotas, size retention against
  job throughput; `10m` is an example, not an automatic configuration change.
- Add correlated lifecycle logs for create, readiness, execution, cleanup
  and tombstone expiration, including process exit code and durations.
- Extend `doctor` with quota headroom warnings using current usage, local-image
  warnings and `--strict`. Operator-only `--installation` checks the Runner
  Secret key, mounted configuration and installation namespace quota.
- Extend `environments inspect` with Pod presence, identity match, cleanup
  action/reason and retention deadline. Cleanup preview uses the configured TTL.
- Require the `runner.yaml` Secret key explicitly in the generated volume.
  Rendered installation comments include container and Pod resource totals.
- Add a [Forgejo + K3s quickstart](../QUICKSTART-K3S.md), a minimal smoke
  workflow, credential handling instructions and image pull guidance.

Validation: `make check` passed. Local Linux/amd64 K3s acceptance covered
admission/RBAC, real packet denials with positive controls, three concurrent
jobs, interrupted-state and process-crash recovery, synthetic API outage,
ConfigMap expiration after exits 0 and 7, and drained rc.1 → current → rc.1
upgrade/rollback. See [validation details](../VALIDATION.md). These tests use
plugin RPCs; successful workflows on the target Forgejo installation remain
to be confirmed. ARM64 artifacts are built but have not been executed on
target hardware.

Upgrade: drain jobs, regenerate admission and installation manifests, and apply
the matching configuration. The default retention remains 24 hours unless you
set it explicitly. `doctor --installation` needs operator credentials; the
controller still cannot read Runner Secrets.

Rollback to rc.4 or earlier: while drained, restore the legacy default-deny
selector `spawnpod.dev/managed: "true"` and omit `tombstoneRetention` from the
old controller's configuration. Restore matching admission and image digests.
Older controllers reject the namespace-wide selector and unknown config fields.
