# SpawnPod v0.1.0-rc.7

Release candidate for controlled source networking. Verify published digests,
signatures and attestations from the completed release workflow before server
installation. The workflow rebuilds and tests the tagged sources before publication.

- Fix the source NetworkPolicy namespace in rendered installation bundles.
- Keep default jobs isolated and select source jobs using a separate official
  Runner plugin alias. Proxy variables are enforced and both NO_PROXY variants
  are cleared for source commands.
- Add explicit `sourceProxyPolicy: pod-selector` for Kubernetes proxy Services
  evaluated after DNAT. The destination combines the infrastructure namespace
  and both fixed proxy labels on one TCP port. Existing exact-IP mode remains
  the default. Source jobs can also reach the selected proxy Pods directly.
- Validate complete initial TLS ClientHello/SNI before dialing upstream; reject
  malformed, fragmented, duplicate and encrypted extensions. Bound connections,
  request lifetimes and shutdown, and add offline proxy configuration validation.
- Reject private and special-purpose route addresses, including IPv6 transition,
  documentation and benchmarking ranges.
- Provide operator-owned, non-root, tokenless proxy Deployment, reserved-IP
  Service, immutable routes and exact ingress/egress policies in the common
  runtime image. See [the source proxy runbook](../SOURCE-PROXY.md).
- Extend release gates with actual network denials, proxy Pod replacement,
  official Runner default/source selection, private checkout and scoped OCI
  transport, plus complete RC6 upgrade/recovery.

Local tests passed on Fedora 43 / K3s v1.34.12, Linux/amd64: source tests,
`make check`, short race suite, vulnerability scan, 39 live network assertions,
two official Runner profiles, private pinned actions/checkout, scoped OCI
push/pull with digest verification and cleanup, and RC6 → RC7 preview → failed
startup → full RC6 rollback → RC7 preview with four successful Forgejo jobs.
A fresh RC7 preview also passed the complete Runner gate, including cancellation
of an observed executing source command, cleaned record and absent job Pod.
Local amd64/arm64 archives passed checksums, versions, platform/revision metadata
and ELF checks. Source and all three amd64 binaries passed govulncheck.
The release workflow gates publication on clean archive builds and signed OCI
publication. Local previews do not establish that signature chain.

## Before server acceptance

Use this release's verified immutable runtime reference from `GHCR_DIGEST` and a
separately pinned official Runner. Keep a full recoverable RC6 bundle and its
Runner Secret. Apply the operator proxy boundary before its Deployment; verify
real positive and negative traffic on the target CNI before enabling source
submissions. Follow the drained upgrade and complete rollback procedures.

## Known limits

- Fedora 44 / K3s v1.36.4 server acceptance will be performed by the operator
  after release. Local metadata-denial probes lack a reachable metadata positive
  control. ARM64 builds do not establish ARM64 execution support.
- Local K3s does not allow a source job to reach the proxy Service using an exact
  ClusterIP IPBlock. Use the explicit selector mode after target-CNI verification;
  do not substitute broad namespace egress or a transient backend-IP pin.
- Policies are additive; inspect all policies selecting source and proxy Pods.
  Anyone who can create/relabel infrastructure Pods can impersonate proxy identity.
- The allowlist permits writes to approved destinations and is not an exfiltration
  filter. Scope credentials separately; the proxy does not terminate upstream TLS.
- The checkout/OCI gate uses a disposable local TLS frontend and an exact private
  node forwarding exception. Production public-route isolation is tested by the
  independent network gate. OCI acceptance covers transport of a ready-made
  artifact; production builders, Hugo and GitOps delivery are outside this release.
- Source acceptance keeps services disabled. No target capacity, HA, mixed Agent
  generations, running-job migration or automatic rollback claim is made.
